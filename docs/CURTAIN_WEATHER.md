# 窗帘点击获取天气 + 窗外景色

## 当前交互

窗帘默认关闭。

现在已经移除 v2 的“天气获取后自动判断开/关窗帘”逻辑。

新流程：

```text
点击窗帘
  ↓
请求浏览器定位
  ↓
请求 Open-Meteo 当前天气
  ↓
成功？
  ├─ 否 -> 窗帘保持原状态
  └─ 是
       ↓
     判断天气场景
       ↓
     预加载对应窗外图片
       ↓
     拉开窗帘
```

窗帘打开后，再点击收拢到两侧的窗帘，会重新获取天气并刷新窗外景色，不会自动关闭。

## 天气图片

```text
src/assets/weather/
  haze.png       # 霾
  fog.png        # 雾
  snow.png       # 雪
  rain.png       # 雨
  overcast.png   # 阴
  cloudy.png     # 多云
  sunny.png      # 晴
```

## 分类规则

`src/features/weather/weatherScene.js`

优先级：

1. 雪
2. 雨 / 雷暴
3. 雾
4. 低能见度且不是 WMO 雾代码 -> 霾
5. 阴
6. 多云
7. 晴

Open-Meteo 的 WMO weather code 没有单独的“霾”代码，因此本项目使用：

```text
visibility < 10000m
且不是 weather_code 45/48
```

作为霾的 UI 近似规则。

## 模块边界

- `weatherController.refresh()`：唯一负责“获取天气 + 更新天气面板”
- `curtainController`：负责响应窗帘点击、等待天气成功、选择/显示景色、拉开窗帘
- `weatherScene.js`：只负责天气 -> 窗外图片分类

这样 B 方向后续调整天气规则时，不需要改窗帘动画 CSS。


## v4 UI / 图层调整

- 左侧“当前天气”卡片已移除。
- 天气仍然只在点击窗帘时请求。
- 成功后在衣柜右上方、窗帘左侧显示：
  - 当前温度
  - 天气描述
- 窗外贴图的 viewport 已按房间原图透明/棋盘格区域精确收紧：
  - x: 1003..1282 / 2048
  - y: 171..432 / 1152
- 天气贴图在该区域内再略向上取景。
- 点击请求天气期间，不再改变窗帘亮度/透明度，也不再做 loading pulse，因此窗帘不会闪烁。
- 显式图层顺序：
  - 窗外景色：低
  - 窗框：高于窗外景色
  - 窗帘：高于窗框
  - 衣柜：高于窗户
  - 人物：最高
